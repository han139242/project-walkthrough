# 座位预约复盘样例

这是可公开的合成项目，包含[变更记录](changes.md)、[当前实现](reservations.py)和[行为测试](test_reservations.py)。要演练无 Git 模式，把此目录复制到一个 Git 工作树之外，指定复制后的目录为复盘对象，再调用 Skill。

```text
用 $project-walkthrough 复盘这个座位预约项目。
讲清重试为什么重复写入、后来改在什么地方，最后给我一段能直接念的介绍。
```

预期讲清三件事：

- 重试重复写入的现象，以及按钮禁用未覆盖重连重试的原因，来自变更记录。
- 源码在写入前按请求编号查历史结果。验证仅覆盖同进程顺序重试。
- Redis 是后来讨论的方案，样例没有跨进程验证。项目更早的搭建顺序也没有被保留。

### 一段口述示例

客户端断线后会用原来的请求编号重试，旧服务会再写一条预约。禁用按钮挡不住重连，所以把检查放到了服务端。现在服务先找同编号的处理结果，已经处理就直接返回。这个样例测过同进程的顺序重试，记录里提到的 Redis 仍是草案。
